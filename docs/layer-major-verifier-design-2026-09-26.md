# Layer-major verifier experiment

The current decode runs all 40 layers for position 0, then all 40 for position 1. This makes two different dependency chains look similar: the recurrent state in each layer must advance in causal position order, while the hidden state for each position must advance in layer order. A short block can satisfy both by running positions in causal order *within each layer*, then advancing the block to the next layer.

The benchmark-only `--bench-target-verifier-layer-major` path does this for N=4 first. It restores a disposable prefix snapshot, embeds the four known candidates, loops over layers outside positions, and completes each layer's deferred expert result before the next position. Existing attention KV and DeltaNet/convolution state thus advance in the same position order as the serial reference. The final LM head uses the prior batched prototype. The timed interval includes embedding, transformer, normalization, and LM head; it excludes candidate generation, state restore/capture, and correctness comparison.

This is a **layer-major multi-position transformer experiment**, not yet a grouped MoE kernel. Experts are still routed and executed per position. The potential saving is temporal locality: all positions access one layer's expert set close together instead of revisiting that layer after traversing the entire model. The existing 512-entry cache retains hot 4-bit experts; cold 2-bit experts bypass it. A second benchmark build adds a 32-slot, per-layer cold-weight staging buffer to reuse cold weights across the four positions. It records reuse counts and routed weight sizes. It does not reduce the number of expert kernel invocations or measure physical SSD/GPU weight bytes.

Correctness compares every position's logits and selected token with serial execution, plus a byte-for-byte final snapshot of KV, CPU recurrent/conv, and GPU recurrent/conv state. One warm-up and five alternating paired trials compare the layer-major path with serial teacher forcing. If N=4 is not at least 15% faster than its paired serial control, the benchmark stops before N=8. That threshold is a practical research gate, not a production acceptance criterion.

A true grouped-MoE verifier would need routing results for the block at each layer, a per-expert list of participating positions, one weight load per unique expert, and a multi-position gate/up/down kernel or equivalent grouped dispatch. The per-layer attention/DeltaNet pipeline would also need per-position scratch rather than its current shared buffers. The layer-major experiment tests whether weight locality alone creates enough headroom to justify that larger refactor.
