### Integrated no-weight state test

`tools/test_c11_native_integration.py` extracts the actual `context_preflight()` and the actual HTTP rejection branch from the pinned `infer.m`, compiles them unchanged except deterministic host-sampler substitution, and executes both8K and32K capacity variants. It verifies source ordering before async drain/session replacement, covers disabled/default policy, invalid environment modes, fresh/continuation exact capacity and plus-one, negative values, INT_MAX-sized accounting, smaller engine limit, low memory, unavailable sample and unchanged CLI behavior.

Rejection executes the real branch's HTTP400 construction, per-request cleanup, close and `continue`. Synthetic resident state includes position, turn7, all ten KV lengths, GDN/convolution sentinel bytes and session ID. It stays byte-identical across rejected requests, and a subsequent valid boundary request is admitted:

- GPU8192: resident position8190, turn7, all ten KV lengths8190 before/after.
- GPU32768: resident position32766, turn7, all ten KV lengths32766 before/after.

This establishes actual preflight/rejection control flow with synthetic preserved state, **not execution of the full native serve loop, transformer, GPU buffers or real model continuation**. The sentinels are not real caches. Source inspection separately confirms the rejection branch precedes resident identity invalidation/restoration. Request/profile metadata loading is not represented as numerical inference.

The real host probe returned less than6GiB, so rejection is the correct result; no allocation or model launch was attempted. Free+inactive is the selected reclaimability proxy, not reserved memory. It neither reserves subsequent growth nor continuously watches pressure.

## Findings for the remediation owner

### V-01 — missing incremental-build prerequisite (P2, confirmed)

`metal_infer/infer.m:56` includes `flash_serve_admission.h`, but `metal_infer/Makefile`'s normal `INFER_DEPS` does not list it. A dry run with a newer isolated target and `-W flash_serve_admission.h` says up-to-date; `-W infer.m` schedules compilation. Thus later header-only admission edits can leave a stale normal binary. The fresh qualification target always compiles and did build correctly here.

Minimal correction: add the header to normal inference prerequisites (and relevant explicit targets if they rely on timestamp dependencies), then retain an incremental-build regression. No runtime or Makefile fix was made in this verification.

### V-02 — empty explicit mode value disagrees with handoff (P2, confirmed)

`flash_serve_policy_mode()` returns disabled for both NULL and empty string. The supplied test explicitly expects empty disabled. The handoff says unset preserves behavior and any explicit value other than1 fails admission. `FLASH_SERVE_QUALIFIED_GPU_ONLY=` therefore bypasses the opt-in envelope instead of failing configuration, as the integrated test demonstrates.

Owner decision required: either reject an explicitly empty value and update the test, or document empty as intentionally disabled and prevent launch configuration from relying on empty as fail-closed. The audit did not change that policy silently. Invalid `0`, `true`, `2` and whitespace-prefixed `1` correctly reject in HTTP mode.

### C11-02 scope — validator passes narrow tests, prerequisite remains OPEN

`verify_release_provenance.py` validates required fields, authorization flag and SHA256 of entries in `files[]`. Tests use only fictional artifacts/manifests in a temporary directory; the positive fixture's true authorization flag is not a claim about real deployment authorization.

The validator does not bind installed_executable/runtime_dependencies/cache_backups fields to hashed `files[]` entries or verify archive contents, launcher mapping, model identity truth or rollback execution. A synthetic manifest naming nonexistent fictional deployment paths still passes if its independently listed synthetic file hashes correctly. This is consistent with its limited output disclaimer; passing it cannot close actual C11-02 provenance. If a stronger role-complete package gate is intended, add explicit schema/role binding and backup/archive verification. No real inventory manifest was supplied or fabricated.
